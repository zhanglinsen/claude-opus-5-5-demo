# 手机端真机验证清单（cf-transport-ship）

对象：`cf-transport-ship` 的 offline / y8 / gamemonetize 三个构建产物。设备：iOS Safari 与 Android Chrome 各测一遍（至少各一台横屏 ≥800 宽的机型；有条件再加一台 667×375 的老 iPhone 和一台带地址栏的 Android）。

**为什么需要这份清单**：实现阶段只有 Node 桩单测与静态几何测试（`tests/unit/mobile/`，全部通过），**没有任何浏览器或真机验证**——性能优化任务在独占浏览器/GPU，本计划期间不得占用。所以下面每一项都是“尚未验证”。

标记含义：
- **[定论]**：代码行为已由读码/单测确定，只需在真机上确认没被平台差异破坏。
- **[推断]**：依赖浏览器/系统的真实行为，只能靠推断，**必须真机验证**。

怎么开：直接打开构建产物；桌面浏览器调试可加 `?touch=1` 强制启用触屏控件。快速进局：`?map=transport-ship&autostart=1&q=low`（`nolock=1` 仅测试用）。
浏览器自动化验收脚本 `scripts/accept-mobile.mjs`（覆盖包围盒、暂停、touchcancel、旋转、后台、E14）**必须在性能任务释放浏览器/GPU、且用户同意后**才能运行，运行方式见脚本头部；它不能替代本清单（headless Chromium 验证不了下面标 [推断] 的多数项）。

## A. 输入与控件（横屏，进入对局后）

| # | 项 | 预期 | 判定 | 标记 |
|---|---|---|---|---|
| A1 | 浮动摇杆 | 在屏幕左侧 40% 任意位置按下，底座立即移到手指下；不动时没有移动；推满速度与桌面 W 键一致 | 手指落点偏离原底座位置也不应“一按就冲” | [定论] |
| A2 | 视角滑动 | 右侧滑动转视角，速度受菜单里的灵敏度影响 | 灵敏度滑块改动后手感随之变化 | [定论] |
| A3 | **点按视角区不开火（E14）** | 快速单击右侧空白处不发射 | 观察弹药数/枪声；重复点 20 次 | **[推断]** 依赖浏览器是否对该 touch 生成合成鼠标事件 |
| A4 | 多指 | 摇杆 + 视角 + 开火同时进行互不干扰；抬起其中一指不影响其余 | 边跑边转边开火 | [定论] |
| A5 | **touchcancel 不卡键** | 按住开火时从屏幕顶部/底部下拉系统栏、切应用手势打断，回来不会一直开火 | 打断后松手观察是否仍在射击 | **[推断]** |
| A6 | “镜”= 右键 | 持步枪：点“镜”开镜；持军刀：**按住**“镜”重击 | 两种武器各试一次 | [定论] |
| A7 | 死亡观战 | 阵亡后点开火键切换观战队友 | 爆破模式阵亡后试 | [定论] |
| A8 | 比分/配装/检视/槽位 | 比分**点按切换**（再点关闭）；配装=B、检视=F；槽位 1–4 直接切武器 | 各点一次；暂停时比分自动关闭 | [定论] |
| A9 | 菜单 ☰ | 打开暂停界面；“继续”恢复，“退出”回大厅；暂停时控件不产生输入 | 暂停后乱点控件应无反应 | [定论] |
| A10 | 按钮热区 | 所有按钮容易单手点中，没有误触相邻按钮 | 人眼 + 手感；按钮最小 44px | **[推断]** |

## B. 页面壳与视口

| # | 项 | 预期 | 判定 | 标记 |
|---|---|---|---|---|
| B1 | **双击/捏合缩放** | 对局中都不会缩放页面 | iOS Safari 重点（它忽略 `user-scalable=no`）；用 `gesturestart` 拦截，需确认有效 | **[推断]** |
| B1b | **大厅/暂停/结算界面的双击缩放** | 这些 `.screen` 界面同样不应被双击缩放；但它们**故意没有** `touch-action:none`（要保留触摸滚动），所以只靠 `user-scalable=no`，iOS Safari 10+ 会忽略它 | iOS Safari 在大厅、暂停界面、结算界面各双击文字空白处；若会缩放，需要给 `.screen` 单独设 `touch-action:manipulation`（同时保留滚动）——这是独立审核指出的点 | **[推断]** |
| B2 | **下拉刷新** | Android Chrome 对局中在屏幕顶部下拉不会刷新 | `overscroll-behavior:none`；试着从顶部往下拉 | **[推断]** |
| B3 | 长按 / 点击高亮 | 长按不弹系统菜单、不选中文字、点击没有高亮框 | 长按按钮与画布各试 | **[推断]** |
| B4 | 大厅可滚动 | 竖屏/横屏大厅仍可触摸滚动（`touch-action:none` 只给了画布与触控层） | 大厅各标签页滑动 | **[推断]** |
| B5 | 地址栏伸缩 | 页面高度用 `100dvh`：地址栏收放时按钮不错位、不被切掉 | Android Chrome / iOS Safari 对局中收放地址栏 | **[推断]** |
| B6 | 旋转重排 | 横↔竖转动后所有按钮按新尺寸重排、不出屏（尤其副开火键） | 转动后目视 | [定论] |
| B7 | **刘海/横条安全区** | 控件与 HUD 不被刘海、Home 横条遮挡 | 目前**未启用** `viewport-fit=cover`（待用户决策 D2），Safari 会自动留白；启用后需重测 | **[推断]** |
| B8 | 全屏按钮 | Android Chrome / iPadOS 出现并能进入全屏，尽力锁横屏；iPhone Safari **不出现** | 各机型确认按钮有无；iframe 内（y8/gamemonetize）确认是否出现 | **[推断]** |
| B9 | iPhone 主屏幕模式 | “添加到主屏幕”后以独立应用打开，状态栏为黑色，画面不被状态栏遮挡 | 我们用了 `apple-mobile-web-app-status-bar-style=black` | **[推断]** |

## C. 生命周期与音频

| # | 项 | 预期 | 判定 | 标记 |
|---|---|---|---|---|
| C1 | 切后台 / 锁屏 | 自动暂停，**声音立即停止**（`audio.js` 有独立心跳，只停循环不会静音，所以代码显式挂起音频） | 对局中按 Home / 锁屏，听声音 | **[推断]** |
| C2 | 返回后 | 停留在暂停界面，**不自动继续**；点“继续”后声音恢复（iOS 需要在触摸手势里恢复） | 回到页面点继续，确认声音回来 | **[推断]** |
| C3 | 来电 / 系统中断 | iOS 上 AudioContext 会进入 `interrupted`；恢复后能出声 | 对局中来电或触发 Siri | **[推断]** |
| C4 | 竖屏对局 | 对局中转竖屏：出现“请横屏”遮罩并暂停；转回横屏遮罩消失，**仍停在暂停** | 转动手机 | [定论] |
| C5 | 竖屏大厅开局 | 竖屏的大厅里直接点“开始”：被遮罩拦下并暂停（方向没变，靠 2Hz 轮询发现） | 竖屏点开始 | [定论] |
| C6 | 广告暂停 | y8 / gamemonetize 广告期间切后台、旋转：不覆盖广告暂停，广告结束后玩家状态正确 | 在平台包里触发广告断点再切后台 | **[推断]** |

## E. 性能（**只记录，不作通过条件**）
移动端渲染与画质策略（动态分辨率、阴影、后处理等）已被排除出本计划（US-M07），需性能任务结束后由用户单独决定。这里只记录数据供那时使用：机型、系统、浏览器、画质档、帧率区间、发热/掉帧现象、加载时间。

## F. 已知未覆盖 / 已知缺口
- **视口高度 < 360**（带地址栏的 Android，约 320–340）：装弹/切枪键会与顶部栏冲突，`layout.js` 有 `test.todo`，尚无紧凑布局。
- `viewport-fit=cover` 是否启用：待用户决策（D2）。
- 高度 < 360 与英文 HUD 溢出这两项在 `layout-geometry.test.mjs` / `hud-geometry.test.mjs` 里以 `test.todo` 记录。
- Playwright 的 Chromium/WebKit 触屏模拟**不能代替**真机验证 B1、B2、B7、C1–C3、B8/B9。
