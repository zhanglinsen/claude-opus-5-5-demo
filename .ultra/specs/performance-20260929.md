## 约束与必要测试

1. 三个 Codex 管理工作树均从上述基线创建；最多三路 GLM CLI。浏览器/GPU 由集成者串行占用，开发路只跑小范围 Node 测试。
2. 采用针对性的测试先行：先证明当前重复写入、分配或搜索开销/寿命缺陷，再修改并验证。不为简单重构堆砌实现细节测试。
3. HUD：稳定帧、分数/弹药/生命变化、语言即时切换、重开/暂停/结算、雷达缓存；动画仍按原帧率。
4. 特效：短/长示踪线生命周期、无对象串用、矩阵/粒子结果及释放；暂停/重开不积累存活对象。不能仅以正常射击截图掩盖数组持续增长。
5. 射线：零轴/竖直/负坐标/边界/角点/极短/最大距离、OBB/坡面、bullet/sight/solid 策略、射线起点在物体内、多命中顺序与 exit；与冻结基线作确定性差分。不得把移动、寻路、地图几何一起重写。
6. 若某路无法在保留行为前提下证明收益，报告无改动或缩小范围；不为消耗额度扩大改动。
7. 不修改用户未跟踪的发布资料/旧视觉报告；不覆盖旧验收原始输出。日志/临时基准/构建产物不进 Git。
8. 审核两轮仍有同一问题，交协调者作具体决策。源代码通过审核才合入；本轮开发任务不自行推送。

## 后续按证据决定

- 若 CPU 热点已下降而 GPU 帧耗时仍占主导，再针对 draw calls、透明过绘、阴影更新和可见性组织下一轮；先分析采样，再给文件分工。
- 如加载仍慢，独立分析目标构建的依赖与资源解析时间；保留离线单文件，不引入运行时外部依赖。
- 本轮不重跑旧 600 秒长测或所有玩法；仅当改动暴露生命周期/规则风险时追加对应验证。
