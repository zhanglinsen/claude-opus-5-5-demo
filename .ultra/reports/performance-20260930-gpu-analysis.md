# GPU 侧采样分析（2026-09-30）

环境：AMD Radeon Pro 5500M（ANGLE Metal），1920×1080，DPR 1，中画质（2×MSAA HalfFloat、2048 PCFSoft 阴影），集成分支 `316cf74` 的构建。

方法：
- 固定种子进局后冻结模拟（`adPaused`），画面照常渲染，场景与机位静止。
- 用 `EXT_disjoint_timer_query_webgl2` 读每帧 GPU 耗时。
- 逐项关闭开销源，每项前后各夹一次基准测量。每张地图测出生点与转身 180° 两个视角。
- 脚本与原始数据：`artifacts/gpu-ablate.mjs`、`artifacts/gpu-ablate-medium.json`、`artifacts/order-test.mjs`（artifacts 不入库）。

## 结论

1. **瓶颈是逐像素着色（填充率），不是顶点、draw call 或阴影。** 半分辨率省 70%；去掉 14 万三角形只省 1.6ms；阴影静态化只省 0.7ms。
2. **天空和海面被放在所有不透明物体之前绘制，存在全屏过度绘制。**
   - 设置：`env.js` 中 `sky.renderOrder = -3`、`ocean.renderOrder = -1`。
   - 后果：物理大气散射与海面着色器（8 波解析法线 + 12 次值噪声）会在被甲板、集装箱、船体遮挡的像素上照样完整计算，提前深度剔除失效。
   - 实测：改到不透明物体之后绘制，四个视角 `readPixels` 逐字节比对均为 0 差异（每帧 829 万字节）。GPU：运输船 58→37.7、53→34ms（约 −35%）；沙漠 37.6→33.3、38.7→33.2ms（约 −12%）。测量时关闭了胶片颗粒和枪模 pass。
   - 这是无画质损失的直接收益，建议下一步实施并做浏览器回归。
3. **点光源成本与亮度无关。** three.js 对每个标准材质像素遍历全部点光源，特效池里 3 个平时亮度为 0 的枪口光仍占 4～7ms。直接隐藏会改变光源数量，引发全场着色器重编译卡顿，不能简单开关。可选方案都涉及画面或实现取舍，需要决策：
   - 地图灯烘焙为自发光或光照贴图；
   - 枪口光池从 3 减为 1；
   - 限制点光源影响范围的自定义材质。
4. IBL（5～16ms）、分辨率（约 70%）属于画质档位范畴；按计划不以降画质证明优化，仅作选项记录。
5. 帧间隔按垂直同步量化（66.7/50/33.3ms 对应 15/20/30 FPS）。GPU 须降到 33ms 以下才能稳定 30 FPS。
